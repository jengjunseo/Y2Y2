# Y2Y2 Personal — 2026-09-12

## What works

On the user's Windows PC, paste a YouTube URL, choose MP4 or MP3, and save a file without ads, a pairing code, a relay account, or browser-cookie extraction. The browser interface and media processor run on the same PC. This is an optional personal edition, not an install-free replacement for the Vercel app and not an Android solution.

Start `engine/windows/Start-Y2Y2.cmd`. Python 3.11+ and Node.js 22+ (or Deno) must already be available. For a source checkout, prepare dependencies once:

```powershell
python -m pip install --no-user --target engine/windows/.runtime -r engine/windows/requirements.txt
```

The prepared output bundle includes Python packages and ffmpeg, using the Python and Node already installed on this PC. No registry change, login/startup service, extension, cookie import, public port or new cloud resource is configured. Keep the whole folder together. Saved media is in `downloads/`; jobs in `personal-data/`. The launch command reopens an existing instance; the page has a shutdown button that refuses to interrupt active jobs.

## Boundaries and implementation

- Binds only `127.0.0.1:49273`; exact Host checking rejects DNS rebinding. Cross-origin and different local-origin requests are rejected. A session bootstrap requires a custom header and cannot be called cross-origin. Mutation/read APIs require a per-process bearer token, held in memory by the page.
- The original engine's queue, retry, cancellation and media processing are reused. Node is detected when Deno is absent. MP4 selection prefers H.264 when available. SQLite connections now close after transactions.
- The legacy pure-web page has bounded requests, a re-entry guard, stricter URL parsing, fallback after cipher-only responses, and a bounded Range reader. Receiving metadata/URLs is no longer labeled download success.
- API/module mocks test state handling, not live downloading. Only the specific observed browser/file path above is claimed live verified.
- Vercel connector listed only another project and returned 404 for `y2-y2`, while GitHub deployment records and the canonical site were accessible. No production replacement, new paid service, permission expansion or merger is performed by this change.
